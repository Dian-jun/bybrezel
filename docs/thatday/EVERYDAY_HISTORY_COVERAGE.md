# 생활사 기록 100건 확장 — 검토 및 실행 안내

검토일: 2026-11-01. **운영 Supabase에는 아직 삽입하지 않았습니다.** 공개 RPC를 7페이지 모두 읽어 기존 639건의 ID·제목·날짜·정확도가 로컬 데이터와 일치함을 확인했습니다. 쓰기용 DB 연결은 없으며 Work 설정에서 로컬 브라우저 제어가 꺼져 있어 실행 가능한 SQL로 준비했습니다.

## 기존 구조 분석

- 사건: `public.thatday_historical_events`. `id` 기본키, `title`, `description`, `date_start`, `date_end`, `date_precision`, `category`, `verification_status`, `review_details`, 생성·수정 시각.
- 날짜: PostgreSQL `date`. `day/month/year/range` 지원. 월·연도만 확인된 경우 기존 규약대로 1일을 저장용 기준값으로 쓰고 정확도를 각각 `month/year`로 보존합니다. 실제 발생일을 1일로 주장하지 않습니다.
- 출처: `public.thatday_event_sources`에 사건별 여러 행. 제목·URL·발행기관·권리 안내·열람일을 저장합니다.
- 기존 카테고리: 역사·사회, 정치, 경제, 문화, 음악, 영화·방송, 스포츠, 기술, 생활. 이번 배치도 이 카테고리만 사용합니다. 여섯 조사 방향은 기존 `review_details` 안의 검토 메모이며 새 콘텐츠 유형이 아닙니다.
- 기존 입력: `scripts/import-history.mjs`의 `normalizeEvent`와 `toSQL`, `supabase/seed.sql`, `research/history/*-additions.json`, `outputs/*history*.sql`. 기본 importer는 upsert와 출처 교체를 수행하므로 이번 배치에서는 검증 함수만 재사용하고 **추가 전용** `tools/thatday/import-history-append.mjs`로 SQL을 생성합니다.
- 기존 스키마·RLS·페이지·HTML·CSS·JavaScript 기능·기존 기록·배포용 `events.json`은 변경하지 않았습니다. 100건의 미검토 Wikidata 후보가 별도로 있으나 이번 검증 기록과 섞거나 승인하지 않습니다. 이번 공개 조회로는 비공개 후보 수를 다시 확인하지 않았습니다.

## 실행

1. `supabase/thatday/008_everyday_history.sql` 전체를 Supabase SQL Editor에서 프로젝트 소유자 권한으로 실행합니다. 기존 테이블과 `review_details` 필드가 있는 현재 DB를 전제로 하며, 예전 스키마 생성 SQL을 다시 실행하지 않습니다.
2. SQL 마지막 조회의 `everyday_batch_events`가 **100**인지 확인합니다. 기존 공개 639건이 유지된 깨끗한 기준에서는 공개 기록이 **739건**이 됩니다. 다른 사람이 이미 같은 사건을 넣었다면 중복 방지로 건수가 적을 수 있으니 검토합니다.
3. 전체 SQL은 한 트랜잭션입니다. 동일 ID 또는 같은 날짜·공백/구두점 제거 제목이 존재하면 해당 사건과 출처를 모두 건너뜁니다. 기존 사건·출처를 UPDATE/DELETE하지 않으며 후속 편집도 보존합니다. 실행 중에는 역사 사건 테이블에만 짧게 쓰기 잠금을 잡습니다.
4. 운영 DB는 아직 639건입니다. SQL 적용 후 기존 연대기의 Supabase 조회에 새 기록이 나타납니다. 배포용 오프라인 fallback 파일은 이번 작업에서 그대로 유지했습니다.

재생성(Git 저장소 `bybrezel` 디렉터리에서):

```sh
node tools/thatday/import-history-append.mjs docs/thatday/everyday-additions.json supabase/thatday/008_everyday_history.sql thatday/data/events.json
```

검증: 기존 데이터와 ID·제목 중복 검사, 날짜/정확도·카테고리·출처 검증. 실제 PostgreSQL 호환 PGlite에서 639 → 739건 삽입, 재실행 후 739건 유지, 기존 사건·출처 전체 보존, 후속 편집 보존, 다른 ID의 같은 사건 삽입 방지를 확인했습니다. 이는 로컬 검증이며 운영 DB 반영을 뜻하지 않습니다.
