# 기억 발굴 × 같은 날, 다른 인생

## 적용

1. Supabase SQL Editor에서 memory-features.sql 전체 실행. 기존 001_archive.sql이 적용된 프로젝트용이며, 새 RPC와 조회 인덱스만 추가합니다. 기존 사용자 기록은 삭제하거나 공개 상태로 변경하지 않습니다. 재실행 가능합니다.
2. Git 저장소의 thatday/index.html, app.js, styles.css를 갱신하고 새 파일 thatday/lives.js도 함께 배포합니다. Supabase URL 및 공개 키 설정은 유지합니다.
3. SQL 적용 후 Git Commit/Push. 운영 DB SQL 적용과 실제 로그인 계정 검증은 별도 필요합니다. 이 공개 키에는 관리자 SQL 실행 권한이 없으므로 자동 적용하지 않았습니다.

## 구현

- 기존 Supabase PKCE 인증, remembered_events 고유 키, localStorage 임시 기억 및 명시적 계정 병합 재사용.
- 선택 즉시 UI 반영, 서버 쓰기 순서 보장, 실패한 ID만 되돌리기. 같은 사건의 중복 요청 방지. 개수는 기억 선택만 집계하며 개인 기록 수와 합산하지 않음.
- 사건별 두 목록: event_id + relation=related / 정확한 하루가 일치하는 독립 기록. 월·연도·기간·무렵을 같은 날짜라고 단정하지 않음.
- 공개 API에는 published+public만 노출. 로그인한 본인에게만 본인 비공개·대기 기록을 표시하고 상태 명시. 다른 사용자의 원본 ID·출생 연도·검수 플래그는 반환하지 않음.
- 각 관계별 5개씩 조회하고 추가 로드. 참여자 수는 실제 remembered_events 집계이며 비로그인 기기 임시 선택은 포함하지 않음. 인위적 사용자·기록을 운영 데이터에 추가하지 않음.
- 기존 바텀시트, 날짜 자동 전달, 관계 선택, 날짜 정확도, 기본 비공개, 공개 명시 동의, 검수, 신고, 수정·삭제 재사용. 저장한 본인 기록은 페이지가 뒤쪽이어도 현재 사건 아래에 표시하고 상태를 구분.
- 계정 전환/로그아웃 즉시 개인 기록 캐시 제거. 글자 크기 14px 중심, 붉은 점과 들여쓰기 사용. 굵기 시각 효과는 글자 폭을 바꾸지 않도록 처리.
- 모바일 visualViewport 높이를 따라 시트 최대 높이 조절, 안전 영역 및 저장 버튼 접근성 유지. 애니메이션 감소 설정 지원.

## 검증

실제 PostgreSQL(PGlite) 통합 테스트 포함 35개 통과. 사건/날짜 관계, 불확실한 날짜 제외, 페이지 제한, 고유 선택·해제와 실제 참여자 수, 타인의 비공개/검토/숨김 기록 차단, 본인만의 기록 노출, 민감 필드 제외를 확인했습니다. 기존 기록 작성·날짜 정확도·권한·검수·신고·수정·삭제 테스트도 유지했습니다.

로컬 PostgreSQL을 연결한 브라우저에서 사건 펼치기, 실제 0명·빈 상태, 기기 기억 선택/해제, 새로고침 유지, 키보드 Enter 조작, 인라인 접기/펼치기, 로그인 연결, 390px 모바일 화면을 확인했습니다. 운영 DB에 테스트 기록을 넣지 않았습니다. 실제 이메일/구글/카카오 로그인, 실물 기기의 소프트 키보드와 로그인한 사용자 저장 후 스크롤은 운영 적용 후 최종 확인이 필요합니다. 현재 Google/Kakao 공급자 활성화는 별도 설정입니다.

JS 구문 검사 및 프로덕션 빌드 통과. 별도 TypeScript/린트 설정은 없는 정적 JS 프로젝트이므로 구문 검사와 기존 테스트를 사용했습니다. 설치/빌드 의존성은 사이트 실행에 추가하지 않았습니다.
